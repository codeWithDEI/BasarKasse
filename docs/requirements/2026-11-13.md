# Personal login QR codes — 13 November 2026

Source: the owner asked what personal till links do and whether QR codes would
make it easier to prepare the six tablets. This extends the assigned-login
requirement implemented in PR #5; it does not add a login bypass.

**BK-REQ-013 — Transfer personal login links by QR code**

The manager shall be able to display a locally generated QR code for an enabled,
event-assigned team member's personal login URL, copy the same link and save the
code as PNG. The card shall identify the person, role/till and event.

Acceptance criteria:

- Decoding the actual rendered QR pixels yields exactly the current deployment
  origin/base path plus `event` and `staff` parameters. No PIN, password or session
  token is encoded, and no link is sent to an external QR service.
- A fresh tablet still needs its personal PIN and any outer website access.
  The authoritative account assignment determines till permissions.
- An existing basket/pending command is preserved; scanning cannot silently
  reassign that work. The ordinary selectable link remains available.
- Selection follows the chosen member; editing an account or changing the event
  closes the previous card. Disabled/unassigned members do not offer a code.
- A PNG download and graceful clipboard-refusal feedback work in the two browser
  engines. Actual camera scanning is part of the physical-device rehearsal.

Implementation: this QR change, pending merge and deployment. Browser tests use
the independent `jsQR` decoder against rendered canvas pixels. See
[operator instructions](../operations/event-teams-and-settlement.md).
